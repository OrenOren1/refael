# ArgoCD Image Tag Update: CI Opens PR

## Context and Problem Statement

After the pipeline builds and pushes a new image to ECR, ArgoCD must deploy the new image. ArgoCD watches the `helm/` directory; it triggers on changes to `helm/values.yaml`. The deploy trigger must be auditable and go through a review gate before reaching the cluster.

## Decision Drivers

* Same-repo GitOps chosen (ADR-005) — values.yaml lives in the app repo
* No direct push to main from CI — changes go through PR review
* Every deploy must be auditable (who, what image, when)
* No cluster-side agent beyond ArgoCD

## Considered Options

* CI opens PR to update image.tag (chosen)
* CI commits directly to main with `[skip ci]`
* Argo CD Image Updater (in-cluster controller)

## Decision Outcome

Chosen option: "CI opens PR", because it enforces a review gate before any new image reaches the cluster, keeps every deploy traceable to a PR, and requires no cluster-side tooling. The pipeline's `update-image-tag` job:
1. Runs `yq e ".image.tag = \"$IMAGE_TAG\"" -i helm/values.yaml`
2. Creates a branch `deploy/image-$IMAGE_TAG`
3. Opens a PR: `chore: deploy image $IMAGE_TAG`
4. On PR merge to main, ArgoCD auto-syncs

Uses `gh pr create` with `GITHUB_TOKEN` (no extra secret needed).

### Consequences

* Good, because no image reaches the cluster without a merged PR — human oversight on every deploy
* Good, because PR history is the full deploy log
* Good, because a failed scan never opens a PR, so the last good image stays deployed
* Bad, because deploy requires a manual PR merge — not fully automated (intentional)
* Bad, because PRs accumulate if deploys are frequent; auto-merge can be enabled when confidence is high

### Confirmation

CI `update-image-tag` job uses `gh pr create`. ArgoCD Application `syncPolicy.automated` enabled — syncs on merge. PR branch deleted after merge.

## Pros and Cons of the Options

### CI direct commit to main
* Good, because fully automated end-to-end
* Bad, because bypasses review; a bad image (passed scan but broken) auto-deploys

### Argo CD Image Updater
* Good, because fully automated, no CI write-back
* Bad, because requires Image Updater + ECR creds in-cluster; no PR review gate
