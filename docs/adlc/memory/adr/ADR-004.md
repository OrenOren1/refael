# AWS ECR as Container Registry

## Context and Problem Statement

The pipeline must push a Docker image to a private registry. The workspace has `AWS_PROFILE=assignment-tests` and `us-east-1` configured.

**Evidence Found**:
* No registry config yet — greenfield
* `.adlc/init-options.json`: AWS profile `assignment-tests` present
* Assignment brief: "private registry of your choice (e.g., Docker Hub, AWS ECR, GCP, etc.)"

## Decision Drivers

* AWS ECR integrates natively with the assignment-tests AWS profile already configured
* GitHub Actions OIDC federation with AWS IAM → keyless ECR push (no stored secrets)
* ECR image scanning (optional) can supplement Trivy

## Considered Options

* AWS ECR (chosen)
* Docker Hub (requires Docker Hub account, stored credentials)
* GitHub Container Registry (viable, but AWS profile already set)

## Decision Outcome

Chosen option: "AWS ECR", because it aligns with the existing AWS setup, supports keyless OIDC authentication from GitHub Actions, and keeps images private with IAM access control.

### Consequences

* Good, because OIDC eliminates long-lived AWS credentials in GitHub secrets
* Good, because ECR lifecycle policies auto-prune old images
* Bad, because ECR requires the K8s cluster to have ECR pull access (IAM role or pull-through cache)
* Bad, because cross-region pulls incur latency and cost if cluster is not in us-east-1

### Confirmation

ECR repository `sample-nodejs` to be created in `assignment-tests`/`us-east-1`. GitHub OIDC provider and IAM role for Actions to be provisioned.

**K8s cluster ECR pull access**: EKS node IAM role granted `ecr:GetAuthorizationToken` + `ecr:BatchGetImage` + `ecr:GetDownloadUrlForLayer`. Pods pull via the node's instance profile — no imagePullSecrets needed.
