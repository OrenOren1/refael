# Kubernetes: EKS (prod) + k3d (local dev)

## Context and Problem Statement

The assignment requires deploying to a Kubernetes cluster accessible by ArgoCD, with Ingress for browser access. Local developer testing must also work without cloud dependency.

## Decision Drivers

* Assignment requires a live cluster with Ingress access + screenshots
* `assignment-tests` AWS profile already configured (us-east-1)
* Developer loop must be fast — no cloud round-trip for local testing
* Ingress controller choice must match what the assignment asks for (nginx-ingress cited)

## Considered Options

* EKS + nginx-ingress (prod), k3d + nginx-ingress (local) — chosen
* EKS + AWS ALB Ingress Controller
* Local-only (kind/k3d)

## Decision Outcome

Chosen option: "EKS with nginx-ingress for the assignment submission, k3d with nginx-ingress for local dev", because:
- nginx-ingress works identically on both EKS and k3d — same Helm values, same Ingress annotations, zero environment-specific divergence
- ALB Ingress Controller is AWS-only, which breaks local dev parity
- k3d ships with nginx-ingress available as an add-on; local stack mirrors prod exactly

### Cluster topology
- **EKS**: `assignment-tests` account, `us-east-1`, managed node group
- **Local**: `k3d cluster create refael --agents 1 -p "8080:80@loadbalancer"` with nginx-ingress enabled

### ECR pull on EKS
Node IAM role granted `ecr:GetAuthorizationToken` + `ecr:BatchGetImage` + `ecr:GetDownloadUrlForLayer`. No imagePullSecrets needed.

### Consequences

* Good, because Helm values.yaml is environment-agnostic — same chart deploys to both
* Good, because local k3d gives instant feedback without ECR push
* Good, because nginx-ingress annotations are well-documented and assignment-familiar
* Bad, because EKS provisioning (nodegroup, OIDC provider, IAM roles) adds setup overhead
* Bad, because k3d requires port-forward or LoadBalancer emulation for Ingress on Mac

### Confirmation

Helm `values.yaml` has `ingress.className: nginx`. EKS context confirmed in kubeconfig. Local: `kubectl get pods -n ingress-nginx` shows nginx-ingress running.

## Pros and Cons of the Options

### ALB Ingress Controller
* Good, because native AWS L7 load balancer, no extra controller to manage
* Bad, because AWS-only — k3d local dev breaks
