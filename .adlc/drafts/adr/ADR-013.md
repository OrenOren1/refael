# Local Dev Task Runner: Taskfile (go-task)

## Context and Problem Statement

Developers need a single entry point to run the full CI/CD cycle locally: linting, security checks, k3d cluster lifecycle, Helm deploy, and Docker build + Trivy scan. Without this, each step requires remembering separate commands and flags.

## Decision Drivers

* Single binary, no runtime dependency (Taskfile is a Go binary)
* Must replicate CI pipeline steps exactly — same commands, same flags
* k3d cluster lifecycle (create/delete/status) must be scriptable
* Security checks (npm audit + nodejsscan) must run offline / without CI

## Considered Options

* Taskfile.dev (`go-task`) — chosen
* Custom Go CLI (Cobra + Viper)
* Makefile
* `mage` (Go-native Makefile alternative)

## Decision Outcome

Chosen option: "Taskfile.dev (`go-task`)", because it is a single YAML config (`Taskfile.yml` at repo root), ships as a single Go binary (`brew install go-task`), supports task dependencies and namespacing, and mirrors CI step ordering with zero additional code.

**Task surface:**

| Task | Command(s) |
|------|-----------|
| `task lint` | `hadolint Dockerfile` + `helm lint helm/ --strict` |
| `task security` | `npm audit --audit-level=high` + `nodejsscan -d . -o json` |
| `task k3d:up` | `k3d cluster create refael --agents 1 -p "8080:80@loadbalancer"` |
| `task k3d:down` | `k3d cluster delete refael` |
| `task k3d:status` | `kubectl get pods -n refael` |
| `task build` | `docker build --load -t sample-nodejs:local .` |
| `task scan` | `trivy image --severity HIGH,CRITICAL --ignore-unfixed sample-nodejs:local` |
| `task deploy:local` | `helm upgrade --install refael helm/ -n refael --create-namespace --set image.tag=local` |
| `task ci` | lint → security → build → scan → deploy:local |

**Local vs CI differences:**
- `task build` uses plain `docker build --load` (local daemon); CI uses `docker build` + ECR push
- `task scan` runs against local image tag `sample-nodejs:local`; CI scans before push to ECR
- No OIDC/AWS credentials needed for `task ci`

### Consequences

* Good, because `task ci` replicates the full pipeline in one command before pushing
* Good, because task dependencies (`deps:`) enforce correct ordering (lint before build, build before scan)
* Good, because Taskfile YAML is readable and self-documenting
* Good, because `task --list` shows all available tasks
* Bad, because requires `go-task`, `hadolint`, `helm`, `k3d`, `trivy`, `nodejsscan` installed locally — documented in README prerequisites
* Bad, because local Docker build uses daemon (not Kaniko); image tag is `local` not semver

### Confirmation

`Taskfile.yml` exists at repo root. `task ci` completes without error on a clean checkout. `task k3d:up && task deploy:local && task k3d:status` shows pods Running.

## Pros and Cons of the Options

### Custom Go CLI (Cobra)
* Good, because full programmatic control, typed flags
* Bad, because significant build/maintenance overhead for what is essentially a script orchestrator

### Makefile
* Good, because universal, no install required
* Bad, because no native task dependency graph, poor Windows support, tab-indentation traps

### mage
* Good, because pure Go, type-safe
* Bad, because requires `go run mage.go` bootstrap; less readable than YAML for non-Go devs

## Constitution Alignment

| Principle | Alignment | Notes |
|-----------|-----------|-------|
| Developer Experience (§5) | ✅ | One command for full local cycle |
| Security by Default (§4) | ✅ | Security checks run before build in `task ci` |
