# Same-Repo GitOps with ArgoCD

## Context and Problem Statement

The assignment requires ArgoCD for GitOps deployment and explicitly offers a choice: separate GitOps repo vs app repo with manifests. This is a solo assignment with one application.

**Evidence Found**:
* No `helm/` directory, no ArgoCD Application manifest yet — greenfield
* Assignment brief: "Choose between: 1. A separate GitOps repository monitored by ArgoCD / 2. ArgoCD pulls manifests directly from your app's repository"
* Single-app scope — no multi-team manifest coordination required

## Decision Drivers

* Single repo simplifies lifecycle: PR merges trigger both app and config changes atomically
* No cross-repo synchronization overhead for a solo assignment
* ArgoCD can watch a specific path (`helm/`) within the repo — no full-repo coupling

## Considered Options

* Same-repo GitOps (app + Helm chart in `OrenOren1/refael`, ArgoCD watches `helm/`) — chosen
* Separate GitOps repo (e.g., `OrenOren1/refael-gitops`) — better for multi-team, multi-app

## Decision Outcome

Chosen option: "Same-repo GitOps", because for a single-app solo assignment the operational simplicity outweighs the GitOps purity argument. The CI pipeline updates `helm/values.yaml` image tag, commits, and ArgoCD auto-syncs.

### Consequences

* Good, because a single PR review covers both code and deployment config
* Good, because no token/deploy-key configuration between two repos
* Bad, because app history and deployment history are mixed in git log
* Bad, because if the pattern is later scaled to multi-app, migration to a separate config repo is required

### Confirmation

ArgoCD Application manifest to point at `repoURL: https://github.com/OrenOren1/refael` with `path: helm` and `targetRevision: main`.
