# GitHub Actions as CI/CD Engine

## Context and Problem Statement

The assignment requires a CI/CD pipeline with SAST, image build/push, Trivy scan, and ArgoCD-triggered deployment. The repo is hosted on GitHub (OrenOren1/refael).

**Evidence Found**:
* No `.github/workflows/` directory exists yet — greenfield pipeline
* Repo is on GitHub — Actions are natively available, zero additional infra
* Assignment brief lists "GitHub Actions" as an example preferred tool

## Decision Drivers

* Native GitHub integration — no separate CI server to provision
* Free for public repos; supports OIDC-based AWS authentication (no long-lived keys)
* Reusable workflows align with the assignment DevSecOps checklist

## Considered Options

* GitHub Actions (chosen)
* Jenkins (requires self-hosted server)
* GitLab CI (different platform)

## Decision Outcome

Chosen option: "GitHub Actions", because it eliminates external CI infrastructure, supports AWS OIDC (keyless ECR push), and has first-class Trivy/Semgrep actions.

### Consequences

* Good, because OIDC federation with AWS IAM eliminates long-lived secrets
* Good, because marketplace actions for Trivy, Semgrep, Helm are well-maintained
* Bad, because GitHub-hosted runners have a 6-hour job limit and limited CPU/RAM
* Bad, because pipeline YAML lives in the app repo, coupling CI config to app code

### Confirmation

`.github/workflows/ci.yml` pipeline to be created. AWS OIDC provider must be configured in `assignment-tests` account.
