# Bonus: Hadolint + Helm Lint in CI

## Context and Problem Statement

The assignment allows optional tooling ("integrate any tool you see necessary"). Two low-effort, high-signal additions: Dockerfile linting and Helm chart validation. Both run in CI before the build step, failing fast on common mistakes.

## Decision Outcome

Add two lint steps to the CI pipeline:

1. **Hadolint** (`hadolint/hadolint-action`) — Dockerfile best-practice linter (ShellCheck + Dockerfile rules). Fails on `warning` level and above. Runs before `docker build`.

2. **`helm lint`** — validates Helm chart syntax and template rendering against `helm/values.yaml`. Runs before the deploy/tag-update job. Command: `helm lint helm/ --strict`.

### Consequences

* Good, because Hadolint catches common Dockerfile mistakes (unpinned apt packages, ADD vs COPY, missing HEALTHCHECK)
* Good, because `helm lint --strict` catches broken templates before ArgoCD sees them
* Good, because both are single-step additions with zero infrastructure cost
* Bad, because Hadolint `DL3008` (apt pin versions) can be noisy on Alpine-based images; suppress with inline `# hadolint ignore=DL3008` where needed

### Confirmation

CI pipeline has a `lint` job: `hadolint/hadolint-action@v3.1.0` on the Dockerfile, `helm lint helm/ --strict` on the chart. Both run before `build` job. Neither requires AWS credentials.
